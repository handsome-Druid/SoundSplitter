# SoundSplitter

[English](../README.md) | 简体中文

把两个独立的音箱组合成立体声音箱：一个播放左声道，另一个播放右声道。SoundSplitter 保持输出音频流同步，并提供独立的声道延迟调整，用于补偿设备之间的固定延迟差。

**支持 Windows 和 Linux。** 使用两个系统能识别的不同音频输出设备。有线、USB 和蓝牙音箱可以组合使用，音乐播放器、浏览器或游戏继续照常使用即可。

> [!IMPORTANT]
> **启动前，务必检查系统中是否存在同名音频设备。** SoundSplitter 使用设备名称而非设备 ID 识别设备，同名设备可能导致非预期错误。请先在系统设置中为同名设备改名，确保名称唯一，再启动程序。建议将两个输出设备分别命名为“左声道输出”和“右声道输出”，便于识别。

## 1. 下载与安装

从[发行版页面](https://github.com/handsome-Druid/SoundSplitter/releases)选择适合系统的安装包：

| 系统 | 安装包 |
|---|---|
| Windows x64 | `.exe` 安装程序 |
| Debian / Ubuntu x64 | `.deb` |
| RPM 系 Linux x64 | `.rpm` |

**Windows：** 运行安装程序，允许管理员权限请求。安装完成后，以普通用户身份打开 SoundSplitter。

**Linux：** 使用系统的软件安装工具或包管理器安装，随后从应用菜单打开 **SoundSplitter**。

## 2. 开始播放

连接两个音箱，确认系统将它们识别为独立的播放设备。左右输出必须是**两个不同的实际设备**，不要选择用于输入的虚拟设备。

以下为首次配置步骤。

### Linux

1. 打开 SoundSplitter，程序会自动创建并选中 **CABLE Input (SoundSplitter)** 输入源。
2. 在“**选择左声道输出**”和“**选择右声道输出**”中分别选择两个实际音箱。
3. 点击“**开始分流**”。
4. 将系统或播放器的输出设为 **CABLE Input (SoundSplitter)**，播放音频。

该虚拟播放设备只在 SoundSplitter 运行期间可用。

### Windows

选择一种输入方式：

| 输入方式 | 系统或播放器的输出 | SoundSplitter 输入源 | 回环采集 |
|---|---|---|---|
| VB-CABLE（需先安装 [VB-CABLE](https://vb-audio.com/Cable/)） | CABLE Input | CABLE Output | 关闭 |
| VB-CABLE 回环采集 | CABLE Input | CABLE Input | 开启 |
| 已有 Steam Streaming Speakers | Steam Streaming Speakers | Steam Streaming Speakers | 开启 |

1. 打开 SoundSplitter。标准 VB-CABLE 输入会自动选中；使用其他方式时，按表设置“**回环采集**”，再选择输入源。
2. 在“**选择左声道输出**”和“**选择右声道输出**”中分别选择两个实际音箱。
3. 点击“**开始分流**”。
4. 将系统或播放器的输出设为表中对应的设备，播放音频。

### 之后使用

设置会自动保存。再次打开 SoundSplitter 后，程序会恢复配置并自动尝试开始分流，无需重复首次配置。

## 3. 进阶调整

更改设备、输入方式或声道延迟前，先停止分流，更改后重新开始。音量和静音可以在播放时调整。

### 只分流某个应用的音频

通过应用自身的输出选择器，或系统中按应用选择音频输出的设置，将它发送到：

- **Linux：** CABLE Input (SoundSplitter)。
- **Windows：** 与当前方案匹配的 CABLE Input 或 Steam Streaming Speakers。

其他应用继续使用原来的播放设备。发送到同一个虚拟设备的应用音频会一起被分流。

### 平衡音量与静音

- 左右音量滑块和扬声器按钮控制各自选定输出设备的系统音量和静音状态，不只影响 SoundSplitter 的音频。
- **Linux：** 分流音频跟随 **CABLE Input (SoundSplitter)** 的音量和静音状态。
- **Windows：** 标准 VB-CABLE 方案会自动为 **CABLE Input** 开启“**音量监听**”。使用其他非回环采集输入源时，可以开启它并选择希望跟随音量的播放设备。

### 对齐延迟不同的音箱

一个音箱比另一个播放得晚时，先停止分流，再将**较快一侧**的“**左声道延迟（毫秒）**”或“**右声道延迟（毫秒）**”增加相应的延迟差。较慢一侧的数值保持不变，然后重新开始分流试听。

例如，如果右侧音箱晚约 `100` 毫秒，就在当前左声道延迟的基础上增加 `100`，再小幅调整试听。

### 语言、开机自启与系统托盘

- 使用语言选择器切换可用的界面语言，所选语言会被保存。
- 开启“**开机自启**”后，SoundSplitter 会在登录系统时于后台启动。
- 最小化窗口或选择“**隐藏到托盘**”，可以让分流在后台继续运行。点击托盘图标可重新显示窗口。如果桌面没有系统托盘，窗口会保持最小化。
- 关闭窗口会询问是否退出，并不等于隐藏窗口。也可以从托盘菜单选择“**退出**”。
- 再次打开 SoundSplitter 会唤回已有窗口，而不是运行第二个副本。

## 4. 常见问题

### 没有声音

将系统或播放器的输出设为上方配置中的虚拟设备，并取消虚拟设备和两个音箱的静音。

### 只有一侧播放

取消无声一侧的静音并调高其音量，使用左右声道都有内容的音频试听。

### 缺少音箱

确认系统能够识别该设备，且设备已启用，再点击 SoundSplitter 中的“**刷新输出设备**”。

### 回声或反馈

使用输入方式表中的虚拟设备作为输入源，左右输出选择实际音箱，避免将播放中的输出再次采集。

### 一个音箱比另一个播放得晚

停止分流，为较快的一侧增加声道延迟以补偿延迟差，然后重新开始分流。

### Windows 使用虚拟音频线时延迟较高

使用 VB-CABLE 等虚拟音频线的非回环采集模式时，可以切换为回环采集，或在 `VBCABLE_ControlPanel.exe` 中调小缓冲样本数。

### 减少重采样带来的音质损失

音频链路的每个环节都可能发生重采样。尽量将采集设备和播放设备的采样率、位深度设为一致。使用 VB-CABLE 时，建议同时对齐 **CABLE Input**、**CABLE Output** 和 `VBCABLE_ControlPanel.exe` 中的内部采样率。

### 延迟、缓冲与音频丢失

- **Windows：** 左右声道延迟默认均为 `0 ms`，应用内部维持最小可用缓冲区。
- **Linux：** 左右声道延迟默认均为 `30 ms`，调小可降低延迟，但应用无法保证最小可用缓冲区。

两个系统都可通过日志文件检查是否发生音频丢失。同时增加两侧延迟可以手动增大缓冲区，有助于缓解音频丢失。

日志位置：

- **Windows：** `%ProgramData%\SoundSplitter\logs\SoundSplitter.log`
- **Linux：** `/var/lib/SoundSplitter/logs/SoundSplitter.log`

### Linux 同一显卡的多个输出只显示一个端点

在 **Pulse 音量控制（pavucontrol）**的“**配置**”中，将对应显卡切换为“**专业音频（Pro Audio）**”模式，以显示全部端点。尽量避免通过系统声音设置手动配置扬声器。

## 5. 停止使用或卸载 SoundSplitter

先将系统或应用的输出改回实际播放设备，再停止分流或退出 SoundSplitter，之后就能不依赖 SoundSplitter 继续播放。

- **Windows：** 在“**设置 > 应用 > 已安装的应用**”中卸载 **SoundSplitter**。想保留设置时，勾选卸载器中的“**保留用户数据**”。VB-CABLE 和 Steam 的音频设备不会被卸载。
- **Linux：** 通过系统的软件安装工具或包管理器移除 **SoundSplitter**。
